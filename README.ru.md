# Boundary Assumption Audit

[English version](README.md)

Скилл для статического аудита ограничений и предположений о масштабировании в небольших и средних программных проектах. Находит риски обрезки результатов, несогласованных ограничений размера, исчерпания ресурсов и хрупких предположений об окружении. Подтверждает выводы исходным кодом и предлагает конкретные решения, не запуская код и тесты и не изменяя проверяемый проект. Работает только по явному вызову.

- **Название репозитория:** `boundary-assumption-audit`
- **Название скилла:** `boundary-assumption-audit`
- **Инструкции скилла:** [SKILL.md](SKILL.md)
- **Лицензия:** [MIT](LICENSE)

## Что проверяет скилл

- Обрезку результатов и преждевременную остановку: пагинацию, лимиты запросов, срезы коллекций, ограничения обхода и числа итераций.
- Управление ресурсами: выделение памяти, очереди, параллелизм, повторные попытки, тайм-ауты и отмену операций.
- Несогласованные контракты: допустимый и сохраняемый размер, ограничения источников и потребителей, значения по умолчанию и единицы измерения.
- Предположения о граничных условиях и окружении: переполнение, специальные значения, пустой ввод, работу в одном процессе или на определённом хосте.

Аудит углубляется в конкретные подозрения на сбой. Обоснованные продуктовые, протокольные, ресурсные и защитные ограничения сохраняются; каталогизация всех числовых констант не является целью.

## Паттерны и принципы проектирования

Они описывают организацию аудита и границы полномочий скилла.

| Pattern / principle | Применение |
|---|---|
| Explicit Activation | Требуется явный вызов; обычный запрос на ревью или отладку не запускает аудит. |
| Least Privilege | Разрешены пассивное исследование и доставка отчёта вне проверяемого проекта. |
| Progressive Refinement | Первичный просмотр значимых путей с дальнейшим разбором конкретных подозрений. |
| Contract Checking | Сопоставление ограничений и предположений между источниками данных, потребителями, хранилищем и конфигурацией. |
| Evidence Traceability | Связь каждого вывода с исходным кодом, условиями возникновения, последствиями и предлагаемой проверкой. |
| Separation of Concerns | Статические выводы, проверка во время выполнения и внесение изменений рассматриваются отдельно. |

## Установка в BB

Файлы скилла должны находиться в папке `boundary-assumption-audit`, имя которой совпадает с полем `name` в YAML-заголовке. Для установки опубликуйте эту папку через плагин Agent Tools в BB:

```text
bb tools skills-publish <path-to-boundary-assumption-audit> --dry-run
bb tools skills-publish <path-to-boundary-assumption-audit>
```

Если BB не определяет исходную машину, добавьте `--host <machine-id>` к обеим командам. Публикация устанавливает скилл в хаб навыков BB. Для обнаружения установленной версии начните новый тред; существующий тред может сохранять прежний список навыков.

Команды требуют BB с плагином Agent Tools. Это инструкции по установке, а не действия во время аудита. Для других сред нужен их собственный механизм установки; совместимость с ними здесь не проверялась.

## Использование

Явно вызовите скилл по имени и укажите репозиторий или подсистему, при необходимости добавив фокус проверки:

```text
Используй boundary-assumption-audit для /path/to/project.
Особое внимание: пагинация и ограничения размера между источниками и потребителями.
```

```text
Используй boundary-assumption-audit для /path/to/project.
Особое внимание: повторные попытки, тайм-ауты и отмена операций.
```

Если путь не указан, используется активный репозиторий. Чтение и обсуждение скилла не запускают аудит.

## Результат

Каждый завершённый аудит предоставляет краткую таблицу выводов в чате и скачиваемый Markdown-отчёт с доказательствами и рекомендациями. Оба результата оформляются на языке разговора. По умолчанию отчёт сохраняется в UTF-8 с BOM вне проверяемого репозитория.

Каждый вывод содержит ссылки на исходный код, серьёзность, уверенность, условия возникновения, последствия и предлагаемые сценарии проверки. Для основной рекомендации используется один из типов действий: `ELIMINATE`, `REDESIGN`, `DERIVE`, `CONFIGURE`, `ALIGN`, `KEEP`, `VERIFY`.

Неподтверждённые опасения остаются открытыми вопросами. Если практических проблем не найдено, вывод об этом ограничивается исследованной областью.

## Границы выполнения

Аудит читает исходный код, конфигурацию, тексты тестов и имеющиеся доказательства. Он не запускает код проекта, тесты, сборки, линтеры, миграции и установку зависимостей; не подключается к базам данных проекта и не управляет действующими сервисами, устройствами или интерфейсом. Предлагаемые проверки явно отмечаются как невыполненные.

Эти ограничения являются инструкциями агенту, а не песочницей операционной системы. Статические доказательства не подтверждают работоспособность во время выполнения и не доказывают отсутствие дефектов. Доставка отчёта зависит от поддержки вложений или скачивания в среде; о сбоях доставки необходимо сообщать.
